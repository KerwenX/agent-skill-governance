冲突检测报告 (7选3风险)

高风险 x3

在从候选集（doc-reader, doc-generate, deep-research...）等技能中交叉比对，发现以下3处并发阻断型冲突：

doc-reader 意图冲突 (Intent)

场景描述：

用户发出“帮我看一下这个文档”时，两个技能的 Description 语义相似度达 0.91。LLM大模型在分发路由时极易产生摇摆、单向覆盖或双重触发。

doc-processing 资源与权限冲突

场景描述：

两技能同时对 Local_Document_Cache 进行独占式写入。在用户执行批量总结时，容易导致底层高并发文件句柄死锁与执行权限被拒。

deep-research 环境与时序冲突

场景描述：

两者高频共享 runtime.python.llm-tier1 运行沙箱，若在相近时序内触发，将触发基础大模型底层MCP接口的频率限制（Rate Limit Overload）。

智能调优与解决策略 (Resolution)

建议采纳

1. 语义解耦（针对意图冲突）

系统已通过大模型重新生成并收窄、优化了 `smart-doc-summarizer` 的 description 内容，增强互斥性：

"专门针对长文本或多PDF文件进行精简、核心要点提炼与摘要生成的智能工具。不执行全文通读与非结构化基础解析。"

2. 资源动态隔离 (针对 doc-processing)

对新技能注入流式排队中间件，限制独占写权限，转为异步多级缓冲区写入。

3. 时序动态抖动 (针对 deep-research)

在并发调用底层MCP大模型接口时，对新技能强制加入 150ms 随机微时序抖动，避开并发洪峰。
