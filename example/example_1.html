互斥防火墙与解决策略 (Resolution & Firewalls)

物理底座绝对锁定 (禁止修改 API Name/Key)

1 针对 🛑 严重冲突：拒绝“优先级缝合”，建立 100% 互斥防火墙

策略：绝对禁止“优先尝试A，报错再调B”。必须为双方分别制定一句话的强边界规则，划定物理隔离带。

✅ 重写: calendar-assistant (动脑推演)

"专用于处理自然语言交互的智能管家。仅当用户需求包含多轮对话、模糊意图推演或未来计划规划时触发。严禁处理单纯的系统级时间戳查询。"

❌ 设限: calendar-custom (翻旧账本)

"底层系统日历只读接口。仅接受标准 Timestamp 格式查询死数据。涉及任何口语化意图或推演操作严禁用本工具，必须交由 calendar-assistant。"

2 针对 🔗 编排越权：剥夺虚假主权，惩罚越界节点

策略：automation-manager 构成了能力造假与流量拦截。必须勒令其删掉泛化触发词及非法指引。

  • 强制移除 automation-manager 描述中的 "可协助创建日程" 等越权声称。
  • 删除其 Prompt 中硬编码的 "If user wants to schedule, call calendar-assistant"，将路由权 100% 交还给顶层 Planner。

3 针对 ⚠️ 轻微重叠：收紧引力重叠区 (Shrink Overlap)

策略：明确区分“单步动作”与“复杂连招”。在 todo-reminder 中追加规则：“仅处理无具体时间块占用的轻量级备忘（如：买牛奶）。若包含具体的起止时间段（如：明早9点到10点开会），强制拒绝并由日历接管。”
