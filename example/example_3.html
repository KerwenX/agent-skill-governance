冲突检测报告 (3处风险)

高风险 x3

在从候选集（stock-indices-query, bank-account-sync, stock-price-query）中交叉比对，发现以下并发阻断型冲突：

stock-indices-query 意图冲突 (Intent)

场景描述：

用户发出“分析一下我的股票和当前行情”时，两者的 Description 在“股票”、“行情”等关键词语义重叠度达 0.88。大模型在路由时极易产生摇摆，可能错误拉起大盘指数查询而忽略用户的个人持仓深度分析需求。

bank-account-sync 生命周期与状态锁阻塞

场景描述：

两技能均需访问 Bank_Account_DB。当网银账单同步技能正在执行底层写入（事务锁定）时，深度分析技能发起的并发大批量读取，会导致数据库触发防脏读机制，产生级联等待与死锁循环。

stock-price-query 目标MCP接口冲突

场景描述：

共同依赖 mcp.finance.market_data。深度分析技能在进行批量持仓回溯时，会瞬间发起大量请求，极易耗尽实时行情API的并发配额（Rate Limit），导致实时查价技能被熔断拒绝服务。

智能调优与冲突解决策略 (Resolution)

建议采纳

1. 语义解耦（针对意图冲突）

系统已通过大模型重新生成并收窄了 `portfolio-analyzer-skill` 的 description 内容，增强与大盘/查价技能的互斥性：

"专注于个人多资产投资组合的收益率计算、风险回撤评估与深度财务建模。注意：不用于查询单一股票实时价格，也不用于查询大盘基础指数行情。"

2. 资源锁降级与事件级联 (针对 bank-account-sync)

注入状态机拦截器，将新技能的读取权限降级为只读快照 (Snapshot Isolation)。或建立事件依赖，强制要求新技能在 `bank_sync_completed` 事件触发后才能执行。

3. MCP接口流量隔离 (针对 stock-price-query)

实施 API QoS（服务质量）分级。将深度分析技能的行情请求路由至“延迟15分钟的行情缓存池”，保障实时查价技能享有最高并发优先级。
